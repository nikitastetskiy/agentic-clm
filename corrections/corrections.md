# Corrections & Learnings

This file is the pipeline's memory. The **pptx-orchestrator reads it before every run** and applies
every applicable rule. This is how the agents "learn and re-adapt": when a human rectifies the
output, capture the lesson here (directly, or via `scripts/capture_correction.py`) and it will be
honored on the next run. Newer rules override older ones on conflict.

Keep rules **short, imperative, and general**. Group by category.

## How to add a correction
```bash
# Quick capture (also logs to corrections.jsonl):
python scripts/capture_correction.py "Vault webinar descriptions: max 1 line" --category events --slide 14 --source human
```
Or just add a bullet under the right heading below.

---

## Global
- Edit existing runs only — never change colors, fonts, sizes, or layout (style is mandatory).
- Hide slides with no fresh data (`show="0"`); never delete a slide.
- Never fabricate versions, dates, titles, URLs, or events.
- Use official product names: "HCP Terraform", "Terraform Enterprise", "Vault Enterprise", "HCP Vault", "Vault Radar".
- Deterministic slide geometry: scripts/map_slides.py extracts each automatable slide's editable shapes (role, x/y, text, hyperlinks) into data/slide-structure.json. run.sh Phase 2b regenerates it against the fresh working copy. Agents (esp. pptx-orchestrator) MUST consume it instead of dumping geometry themselves — this was the biggest time/quota sink.
- Deterministic post-build verification: scripts/verify_deck.py machine-checks the produced deck (integrity/slide-count vs original, hide audit via <p:sld show=0> on slide ROOTS, style_check, and that each release slide's latest/col3 column carries products.<p>.latest.version). run.sh Phase 4b runs it before the AI reviewer and writes output/verify-*.txt, which the reviewer reads as ground truth instead of eyeballing XML. This replaces ad-hoc manual XML checks and prevents the two mistakes seen on run 1558: the reviewer's false hide-FAIL (it checked presentation.xml) and a human mis-reading variable-entry columns as 'bloat'. The verifier also prints entries-per-column so the hand-curated multi-entry layout is self-evident.
- Repointing a run's hyperlink via add_rel/relink_run mints a fresh rId and leaves the run's PREVIOUS hyperlink rel dangling in the .rels (reviewer found slide7 rId11 -> an old v1.16.0-alpha tag). All three deterministic editors now call pptx_edit.prune_orphan_hyperlinks(slide_dom, rels_dom) before writing: it removes ONLY relationships of the hyperlink Type whose Id is referenced by no element (r:id/r:embed/r:link) — so implicit/internal rels (slideLayout, image, notesSlide) are never touched. verify_deck also treats a stale/None product latest as satisfied (slide correctly left unchanged).
- ROOT CAUSE of the silent review/learning failure (run 1150): verify_deck's checks encoded the WRONG defaults, so a deck with empty webinar slots, a blanked blog box, and a skipped same-month release was OVERALL PASS — the AI reviewer faithfully reported it as correct, and the learning loop (which only records FLAGGED defects) learned nothing. Fix = make the verifier's defaults match the hand-authored standard: added Check 8 (no_empty_box) and Check 9 (release_gap) as hard FAILs. Lesson: the verifier is the source of truth for 'correct'; if it tolerates a defect, the whole review+learning loop is blind to it. Encode every human-stated standard as a deterministic gate, not just agent prose.

## Releases (slides 7, 8, 11, 12)
- Vault version numbers: base semver only — strip `+ent`, `+ent.hsm`, `+ent.fips` (e.g. `v1.21.8`).
- Show stable releases only; never list alpha/beta/rc as a current release (a clearly-labelled
  pre-release callout is fine where the template already has one).
- Highlights: one concise present-tense sentence, ≤ ~18 words, benefit-led, no marketing fluff.
- Terraform Enterprise releases.json uses calendar versions (vYYYYMM-N) and can lag the deck's 2026 semver entries; verify TFE source freshness and never downgrade slide 8 to older data  _(slide 8)_
- When Vault release highlights are unavailable, leave slides 11/12 unchanged and flag for manual highlight entry; never pair new versions with stale/blank highlights  _(slide 11)_
- Vault changelog_url must point to the PUBLIC hashicorp/vault main CHANGELOG (blob/main/CHANGELOG.md); the releases API url_changelog points at the private vault-enterprise repo and per-version public tags don't all exist. Agent fetches the consolidated changelog once and greps the '## <version>' section for each highlight.
- HCP Vault (slide 12) tracks the same Vault core versions as Vault Enterprise (slide 11); when 11 gains a new June release and 12 has no June column, flag 12 for manual structural update rather than silently shipping it a release behind  _(slide 12)_
- Release slides (7,8,11,12) are a ROLLING 3-column window driven by products.<product>.latest in releases.json, NOT a full rewrite. Each column is a (month-header, entry) pair; col3 is always the latest. Rule: if latest.month_label == current col3 header month, refresh col3's entry in place and leave col1/col2 untouched; if latest's month is newer, shift the (header,entry) pairs one column left (col1<-col2, col2<-col3, oldest drops) and write latest into col3. NEVER blank or rebuild all 3 columns from the API (it caps at 20 items; for Vault all same-month backports, so col1/col2 history can't be re-derived and must be preserved). Slides 11 (Vault Ent) and 12 (HCP Vault) use the same vault.latest but apply the rule independently against their own columns (12 may lag) — goal is neither stays a month behind; they need NOT be byte-identical. The build reads data/slide-structure.json (from scripts/map_slides.py, regenerated each run in run.sh Phase 2b) for exact shape roles/geometry so it never re-discovers layout.
- RETRACTED (was "COLUMN BLOAT FAILURE", run 1558 — the diagnosis was WRONG). The original deck's release columns are HAND-CURATED and already contain a VARIABLE number of version entries per column (verified in the original: slide 7 col2/May lists 5 patches v1.15.4..v1.15.1; slide 7 col1/April lists 2; slide 11 col1 March/April lists 3 incl. v2.0.0 with sub-bullets). The build did NOT bloat anything: it correctly preserved col1/col2 verbatim and only refreshed col3 with products.<product>.latest. CORRECT STANDARD: a column may hold 1+ entries; NEVER collapse a multi-entry column to one; refresh col3 (or shift on a new month) and leave col1/col2 byte-identical. recent_count is irrelevant to the build (it renders `latest`, not recent[]).
- Release-column version runs can SHARE one hyperlink rId with another entry: slide 11 col3 v2.0.2 and col2 v2.0.1 both use rId6 -> tag/v2.0.1, so the v2.0.2 'tag' link actually points at v2.0.1 (pre-existing in the source deck). Verify each version run's hlinkClick rId resolves to ITS OWN vX.Y.Z tag; when refreshing/adding an entry, give it its own rel rather than reusing a shared one (the build correctly minted rId8->v2.0.3).  _(slide 11)_
- A release's authoritative identity is its DATE, not the printed version string: original decks can mislabel a version (e.g. slide 7 showed '1.15.4 (2026-05-27)' but that date is really 1.15.5, and even its hyperlink pointed at v1.15.5). Reconcile every dated entry against releases.json keyed by exact date; the API data wins, the hyperlink is corroborating-only (never the sole basis for a change). This is now enforced deterministically by scripts/edit_release_slides.py (reconcile pass) and guarded by scripts/verify_deck.py Check 5 (release_accuracy).  _(slide 7)_
- Release slides 7,8,11,12 are edited deterministically by scripts/edit_release_slides.py BEFORE the build agent; it writes data/release-edit-report.json with fallback_slides[] (ambiguous, agent handles) and handled_slides[] (done, agent must not re-touch). When fixing a release-slide hyperlink, mint a FRESH relationship id (rIds are often SHARED across entries — mutating a shared rel's Target corrupts a sibling entry's link).
- When refreshing/replacing a release-entry paragraph (e.g. col3 latest), also clear or repoint any stale <a:hlinkClick> left inside that paragraph's <a:endParaRPr> — it is non-visible cruft (slide 7 v1.15.6's endParaRPr still pointed rId6->v1.15.5) that makes link audits chase a phantom second target. Verify hyperlinks per VISIBLE a:r run, not per-paragraph aggregate.  _(slide 7)_
- Changelog highlights are now extracted DETERMINISTICALLY by scripts/fetch_changelogs.py (Phase 1), not the deck-data agent. It resolves each entry's changelog_url to its raw.githubusercontent.com form, fetches each distinct file once, slices the '## <version>' section, and picks ONE bullet by category priority (FEATURES>ENHANCEMENTS>SECURITY>CHANGES>BUG FIXES), stripping PR refs/markdown to a one-line sentence. Stores 'highlight' + (on latest) 'changelog_excerpt'. The agent only LIGHTLY polishes wording from the local excerpt — it must NOT web_fetch changelogs. Cut deck-data web I/O massively.
- Terraform Enterprise releases are now fetched DETERMINISTICALLY by scripts/fetch_tfe_releases.py (Phase 1). The releases page is a Next.js doc: parse __NEXT_DATA__ and match each release row's anchor '/terraform/enterprise/releases/<year>/v<version>' (robust). Calendar versions vYYYYMM-N yield month/year directly. FRESHNESS GUARD is deterministic: read the ORIGINAL deck slide8's max 'Terraform Enterprise vX (YYYY-MM-DD)' date and if the newest fetched release date <= that, set recent=[]/latest=null/status='stale_source' (never downgrade). The agent no longer web_fetches the page or digs git history.  _(slide 8)_
- Same-month release patches must NOT be dropped as historical. Old editor REPLACED col3's top entry on a same-month update, overwriting vault 2.0.2 with 2.0.3 (slide 11), and could not shift slide 12's multi-entry columns at all. Fixes: fetch_releases.py adds products.<p>.month_window (all same major.minor releases in the API window) and fetch_changelogs.py gives each a highlight; edit_release_slides.py now (a) ADDS latest ABOVE an existing distinct stable col3 entry instead of replacing it, (b) has a generalized shift_new_month that handles ANY per-column entry counts by moving entire entry paragraph-groups (style/links intact) and builds the new month column from ALL that month's month_window releases, and (c) runs ensure_month_complete to splice in any missing same-month patch. Result: slides 11 AND 12 show 2.0.3 AND 2.0.2. Guarded by verify_deck Check 9 (release_gap).  _(slide 11)_
- Completeness is a property of the WHOLE displayed release window, not just the current month. The skipped-patch you flagged (HCP Terraform missing a May .x patch / the 1.15.5 mislabel cascade) lived in a HISTORICAL column (May, col2), but Check 9 and the editor's completeness pass were scoped to the LATEST month only — so a historical gap could ship. Fixes: (a) edit_release_slides.ensure_window_complete now runs ensure_month_complete for EVERY month present in month_window, and runs UNCONDITIONALLY on non-fallback slides (even when 'latest already present; no shift needed'), so a historical gap with no new release is still repaired; (b) verify_deck Check 9 audits every DISPLAYED month column (a month entirely absent has scrolled off the rolling window -> skipped; a partial month -> FAIL). Proven: synthesizing a missing May 1.15.4 makes Check 9 FAIL, and the editor splices it back to 9/9 PASS.  _(slide 7)_

## Blogs (slides 9, 13)
- Update the `See here` hyperlink target in the slide `.rels`, not just the visible text.
- Keep the topic tag chips (Speed & agility, AI, …) unchanged.
- Blog slides may carry pre-existing entries BELOW the refreshed newest-first top list that are not in blogs.json and may sit out of strict date order (slide 13 'June 4 - Rethinking infrastructure access' renders under May entries). The build only refreshes the top of the list from blogs.json; do not flag these lower curated/out-of-order entries as build errors.  _(slide 13)_
- Blog slides 9 (Terraform) and 13 (Vault) are now edited DETERMINISTICALLY by scripts/edit_blog_slides.py (run.sh Phase 3c) BEFORE the build agent. It refreshes the top N = len(blogs.products.<product>.recent) entries: rewrites the date run (preserving leading whitespace + ' – ' separator, formatting the date as full-month '%B %-d' e.g. 'June 16'), collapses the full post title into the first title run (removing surplus title runs — Google-Slides export bold splitting is noise, not semantic), and repoints the 'See here' hyperlink via a FRESH rel (shared rIds are never mutated). Older entries below the top N are left as history. The build agent must NOT touch slides 9/13. Guarded by verify_deck Check 6 (blog_coverage).
- Blog refresh must de-duplicate the newly-written top-N posts against the preserved tail entries on the SAME slide: if a refreshed newest-first post equals a curated lower entry (slide 13: 'SCIM in HashiCorp Vault standardizes provisioning in platforms', May 28), drop/replace the duplicate so the same blog is not shown twice. Distinct from the out-of-order-tail rule (which is acceptable).  _(slide 13)_
- Blog top-N refresh can DUPLICATE a post: the feed window (blogs.json recent[]) overlaps the deck's curated history, so a refreshed top-N entry can equal a preserved lower 'tail' entry (e.g. slide 13 showed 'SCIM ... May 28' twice). edit_blog_slides.py now DE-DUPS: after refreshing the top N, it scans tail entries (index>=N) and BLANKS any whose blog URL (locale/scheme/trailing-slash-normalized) OR title matches a refreshed post. Guarded by verify_deck Check 6 (blog_coverage) which now also FAILs on any repeated blog entry text.  _(slide 13)_
- Blog slides 9/13 now use INSERT-AND-SHIFT, not overwrite-top-N+blank. The old approach overwrote the top entries (losing curated posts) and BLANKED a tail entry that duplicated a refreshed post -> an empty box (slide 13). SUPERSEDES the earlier 'de-dup by blanking the tail' rule. New edit_blog_slides.py: reads all 8 existing entries, computes which blogs.json posts are genuinely new (not already shown), inserts those at the TOP, shifts every existing entry DOWN one, lets the oldest fall off the bottom — all 8 boxes stay filled, nothing overwritten or duplicated, no empty box. No-op (byte-stable) when there are no new posts. verify_deck Check 6 (blog_coverage) rewritten to insert-and-shift semantics (new posts at top, no fixed top-N demand) and Check 8 fails on any blanked box vs the original's entry count.  _(slide 13)_

## Events / Webinars (slides 10, 14, 18–22)
- Only include events whose date is today or later.
- Featured events 18–22: one event per slide; hide extras when there are fewer events than slides.
- Slide 22 is a French-language (Paris) event — keep locale/language if it is reused.
- Verify the hide step by checking `<p:sld ... show="0">` on each SLIDE-ROOT file (ppt/slides/slideN.xml), resolving display position -> file via presentation.xml + rels (use `python scripts/hide_slides.py UNPACKED --list`). Do NOT count `show` on `<p:sldId>` in ppt/presentation.xml — PowerPoint's "Hide Slide" sets the attribute on the slide root, not on sldId, so checking presentation.xml yields a FALSE "zero hidden" (this caused a bogus FAIL on run 1558, whose 10/14/18–22 WERE correctly hidden). Also: a hidden slide RETAINS its text, so seeing past-dated text in slideN.xml is NOT evidence the slide is visible — check the show attribute.
- When events.json status == 'unavailable' (e.g. HTTP 429, not a confirmed-empty fetch), pick ONE policy and make build notes match the deck: either hide event slides 10/14/18-22 (show="0") or leave them unchanged — but never ship past-dated (< today) webinars/events as visible.
- The HashiCorp events page (hashicorp.com/en/events) is behind a Vercel Security Checkpoint (JS challenge) that 429s BOTH plain HTTP and the agent's web_fetch. The reliable fix is a headless Chromium (Playwright): it executes the challenge JS, gets the clearance cookie, and the real page renders (title 'HashiCorp Events'). scripts/fetch_events.py now does this deterministically. Event cards are line-structured text: line0='MON D, YYYY' date, line1=TYPE (WEBINAR/CONFERENCE), line2=title, then product tags (Terraform/Vault/...). Bucket webinars by PRODUCT TAG (reliable), not title keywords; CONFERENCE/in-person -> featured. The sitemap (hashicorp.com/sitemap.xml) IS reachable but lists event URLs without dates, so it can't drive 'upcoming'. Python writes the facts (date/title/url/products); the deck-data agent only fills description/location prose and must NOT change facts when status=='ok'.
- Featured slide 22 locale fallback: the slide-map marks it French (Paris) and says keep locale if reused, but when events.json has NO upcoming French event it is acceptable to reuse slide 22 for the next-soonest English featured event (keeps the slot productive) rather than hiding it — provided the locale switch is noted in build notes.  _(slide 22)_
- Event slides are now edited DETERMINISTICALLY by scripts/edit_event_slides.py (run.sh Phase 3d) BEFORE the build agent: webinar slots (10,14) and featured (18-22). Slots are filled in READING ORDER (sort by rounded-y then x) with events sorted SOONEST-upcoming-first (ascending date) — this is the agreed ordering for 'upcoming' slides (matches what a human expects and the prior agent's featured output); slide-map fill is now 'soonest_first'. Webinar slot p0 = '<DATE upper> | WEBINAR | ' + 'See here'(link); p1 = title; p2+ description bullets collapse to the single events.json sentence (delete surplus <a:p>). Surplus slots are cleared to a single empty '<a:p><a:endParaRPr lang=en-US/></a:p>'; a product with zero webinars HIDES the slide (show='0'). Featured: Title 1=title, Subtitle 2='Event | <display_date> | '+'Register Here'(link), Content Placeholder 4=description (collapse to 1 para); slides past the supply are HIDDEN. All hyperlinks use FRESH rels (slide 14 slots SHARE rId4 in the source deck — mutating it would corrupt siblings). The build agent must NOT touch 10/14/18-22. Guarded by verify_deck Check 7 (event_coverage).
- Featured/webinar event slides retain a non-visible <a:hlinkClick> inside <a:endParaRPr> after refresh (slide 20 endParaRPr -> old kpnhpdmb, slide 22 -> automationday-jun11-Paris). edit_event_slides.py repoints the visible Register Here run but not the paragraph-end link, so link audits chase phantom targets. Clear or repoint endParaRPr hlinks too (same fix already applied to edit_release_slides.py). Harmless to readers (no glyphs) but flag in audits.  _(slide 20)_
- Webinar slides 10/14 must NEVER show an empty slot. The hand-authored deck always filled every slot, backfilling with certification/cross-product/regional webinars (and, when needed, featured events). fetch_events.py now keeps a full pool: webinars.other[] holds untagged/cert/cross-product webinars (previously DROPPED), and slots carry products[]/type. edit_event_slides.py allocates GLOBALLY: each slide takes its own product's webinars first, then backfills remaining slots from (other-bucket + other-product webinars + featured NOT already on 18-22), soonest-first, relabeling the slot's '| WEBINAR |' segment to the event's type (e.g. '| CONFERENCE |'). Featured shown on 18-22 are reserved/excluded so nothing appears twice. Guarded by verify_deck Check 8 (no empty slot on a VISIBLE webinar slide).  _(slide 10)_
- Slide 14 (vault webinars): all 4 slots must be filled; if fewer than 4 vault webinars exist, backfill remaining slots from featured events NOT already on slides 18-22, soonest-first. Never leave a slot blank.  _(slide 14)_
- Webinar slide backfill must be soonest-first: sort all candidate backfill events by date ascending and pick the earliest ones not already on slides 18-22. Never skip over nearer-date events to pick a later one.  _(slide 14)_
- Webinar slide slot order must be soonest-upcoming first (ascending date). Fill slot 1 with the nearest event, slot 2 with the next, etc.  _(slide 14)_
- Featured event slides (18-22): the date-prefix run (e.g. 'Event | June 24 | ') must have its hlinkClick repointed to the same URL as Register Here, not a stale URL from a previous slide assignment. Add a fresh rel for the event URL and apply it to both the date-prefix run and the Register Here run.  _(slide 20)_

## Style
- Terraform slides use purple (`8B85FF` / `7B42BC`); Vault slides use gold/orange (`F9B373`).
  Never swap a product's accent color.
- Reviewer: diff a:t text via XML DOM (getElementsByTagName('a:t')), not a <a:t>...</a:t> regex; deck-wide xml:space=preserve repairs and <a:tab> elements cause false text-diff positives on out-of-scope slides
- When removing or replacing a linked release entry (e.g. swapping a pre-release col3 entry for a stable one), also PRUNE the now-orphaned <Relationship> from ppt/slides/slideN.xml.rels. clean.py removes unreferenced media but NOT unreferenced hyperlink rels: slide 7 left rId11 -> v1.16.0-alpha20260603 fully orphaned after v1.15.6 replaced the alpha. Harmless but makes link audits chase phantom targets.  _(slide 7)_
